## 1. 목표

표·중첩 표 인식을 확인한 PDF2IR POC를 최신 devel 기반 작업 브랜치에 통합하고,
제품 CLI와 WASM이 PDF 바이트에서 공통 Document IR을 생성하여 기존 렌더/저장 경로를
사용하도록 한다. 독립 POC 도구를 저장소에 보존하는 것만으로 완료하지 않는다.

브라우저/확장을 1급 소비자로 유지한다. 서버, Python, native 전용 PDF 라이브러리,
원격 OCR을 기본 실행의 필수 의존성으로 만들지 않는다.

- 실제 한컴 UI에서 편집한 뒤 저장·재열기하는 흐름은 미검증이다.

## 3. 구현 설계에서 확정할 계약

1. **의존 방향:** PDF 추출 → 영역/구조 인식 → lowering → 공통 Document IR.
   제품이 POC 실행파일이나 POC의 root rhwp 의존에 역으로 의존하는 순환을 만들지 않는다.
   별도 crate/module 선택과 공개 진입점은 실제 source 의존 관계 조사 뒤 구현계획에서 정한다.
2. **직접 IR 생성:** HWPX를 임시 저장하고 재파싱하는 경로를 PDF 입력의 필수 구현으로 삼지 않는다.
   기존 HWP/HWPX 파서·모델·렌더러 계약을 재사용하고 PDF 전용 추론은 adapter가 소유한다.
3. **입력 API:** CLI의 PDF 입력/변환과 WASM의 바이트 입력을 명시적으로 지원한다.
   감지와 import API의 경계, feature 기본값·비활성 오류, 기존 공개 API 호환성을 정한다.
4. **페이지 계약:** 전체 입력/명시적 선택 쪽, 원본 쪽 대응, continuation과 페이지 크기를 정한다.
   첫 쪽만 조용히 처리하거나 미지원 쪽을 누락시키지 않는다. 지원 불가 시 오류/경고와 범위를 반환한다.
5. **문단 계약:** 시각적 줄은 관측값, 문단 경계는 추론 결과다. 임시 문단 정책·줄 근거·제한을
   진단에 보존한다. 페이지/단 이동을 논리 문단의 확정 경계로 취급하지 않는다.
   문단 경계 알고리즘 고도화 자체는 후속 과제로 구분한다.
6. **LineSeg 계약:** 좌표 원점·텍스트 축·물리 단위·출처와 캐시 유효성을 명시한다.
   한컴 Print 통과를 편집 재조판 완료로 바꾸지 않고 공통 IR 규약을 POC에 맞춰 완화하지 않는다.
7. **호환성 보정:** POC의 HWPX 후처리와 실제 IR 생성 책임을 조사한다.
   제품 serializer 변경이 필요하면 위반 계약·독립 재현 근거·기존 포맷 영향과 검증을 별도 명시한다.
8. **안전한 실패:** 손상/암호/미지원/예산 초과를 구분하고 실패 뒤 다음 정상 문서 열기를 검증한다.
   수치 예산은 선행 할당·압축·CPU 소비 위치까지 추적하고 입증되지 않은 안전성을 주장하지 않는다.
9. **비용:** 라이선스·전이 의존성·root lockfile·feature 조합·WASM 크기·시간/메모리를 측정한다.

## 6. 완료 조건과 비범위

완료는 제품 CLI와 WASM이 승인된 범위의 PDF에서 공통 IR을 생성하고 기존 렌더/저장 경로로
처리하는 것이다. 임시 출력·POC binary를 우회 호출하는 것만으로 완료하지 않는다.

범용 OCR, 스캔 문서 인식, borderless/모든 혼합 테두리, 원본 embedded font 완전 복원,
문단 의미의 완전 복원, Studio/확장의 UI 전면 개편은 이번의 자동 포함 범위가 아니다.
제품 입력 연결에 꼭 필요한 UI 변경이 있으면 영향과 별도 게이트를 구현계획에 명시한다.
기존 HWP/HWPX 처리·정상 출력·공개 API를 보존하고 새 회귀는 구현으로 해결한다.
